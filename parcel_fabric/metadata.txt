about=Parcel Fabric brings the ArcGIS Pro parcel fabric workflow to QGIS. Every line, point and parcel belongs to the legal record (plat, deed, survey) that created it. Enter courses by hand or paste a metes-and-bounds description, check closure, write COGO-attributed lines with true circular arcs, then Build turns closed loops into parcel polygons and corner points with misclose and area computed from the record dimensions. Check Fabric finds open loops, missing COGO and poor closures. Works in a GeoPackage or any database QGIS connects to (PostgreSQL/PostGIS, SQL Server, Oracle). Field names match the ArcGIS Pro parcel fabric so data moves between them. Pure Python, no external dependencies. Independent of Esri.

changelog=
    0.10.16 - Merge no longer fails to build a parcel cut from the side of its neighbor (rather than fully enclosed): the touch check's own buffer trick could leave a near-zero-area sliver alongside the real merged shape, and a later count of "how many pieces should this be" compared against that phantom sliver instead of the real result, rejecting a build that had actually worked. Confirmed against real Columbia County parcel data.
    0.10.15 - Merge no longer calls parcels "not touching" when they actually do: a parcel cut from the side of its neighbor (rather than fully enclosed) could come back from the touch check as several pieces a hair apart even at zero gap, and got rejected outright. The check now only rejects parcels whose measured gap is really over tolerance.
    0.10.14 - Merge checks each parcel's shape first and names which one is invalid, instead of failing the touch check for an unrelated reason. When parcels genuinely don't touch, the error now gives the actual gap and the fabric's tolerance, so a shared edge that's merely a hair off (fixable with Align Edge or Check Fabric) isn't confused with pieces that are truly separate.
    0.10.13 - SQL Server parcels store several polygons as one MultiPolygon. Opening an existing SQL Server fabric switches Parcels to MultiPolygon; the polygons already stored stay. Curves on a SQL Server parcel, and on imported subdivisions, lots, and blocks, are stored as straight segments. GeoPackage and PostGIS still keep true curves. A table that still holds one polygon per parcel keeps each part as its own current parcel. Import traces boundaries in memory instead of asking SQL Server once per edge, and numbers or outlines already in the fabric are reported separately from parcels that were left out. Create Missing Lines shows how many parcels are done and how many are left. More, Default Style restyles the fabric and shows points from 1:4,000, lines from 1:12,000, lots from 1:24,000, and blocks from 1:50,000, and closer.
    0.10.12 - Import Parcels can take book, page, created-by, and last-edited-by from source fields (a blank field uses the typed book and page). The parcel, its new record, and the lines and points traced from it store CreatedByUser and EditUser; a blank source user stays blank, and a shared corner keeps the first parcel's names. While those lines are traced the progress label reads "Creating lines: 1/37000". Opening a fabric adds EditUser. Check Fabric reports an empty parcel, a self-crossing straight parcel, and a repeated vertex, and the issues window marks them on the map with Zoom to Error. Records and Traverse share one dock. Daily tools use Alt+Shift+R, T, B, N, and C.
    0.10.11 - Import Lots, Subdivisions and Blocks no longer drop a multi-part shape as "more than one polygon": these tables are reference labels, not parcels, so a new fabric now always makes them plain multi-polygon (like Records' own footprint already was), and on an older fabric whose table still holds one polygon per row, a multi-part shape imports as several same-named rows instead of being skipped.
    0.10.10 - New Fabric on SQL Server no longer fails with "Invalid object name 'geometry_columns'" on a plain new database (one not set up by ArcSDE or similar): QGIS looks up spatial tables by querying an OGC-style geometry_columns table, falling back to scanning sys.columns, as one query - so a database with neither fails that lookup outright, on something as simple as checking a table exists yet. An empty geometry_columns table is now created first if needed.
    0.10.9 - Split, Divide, Merge, Separate, Copy Parallel, Subdivide Block and Stacked Unit can set the active record straight from the parcel(s) you've selected ("Use selected parcel's record"), instead of requiring a trip to the Records panel first. Fabric Settings > Maintenance: Create Indexes (on the fields every current-parcel query filters or joins by), Update Statistics and Reclaim Space, for a fabric that only grows (nothing is ever deleted). New Create Missing Lines and Points tool: the same boundary tracing Import Parcels does for new rows, run on parcels already in the fabric that don't have it (an older import, from before 0.10.8, say).
    0.10.8 - Import Parcels now traces each parcel's boundary lines and corner points afterwards, sharing a line between adjoining parcels instead of duplicating it, so Build, Merge and Split have something to work with - importing used to leave parcels with no lines at all, so two imported parcels that shared a side could not be merged ("couldn't be built").
    0.10.7 - Split Parcel: a click to start or end the cut line near the selected parcel's own edge (not only at an existing corner) now lands exactly on it, instead of being rejected as not reaching the boundary; the window explains how to cut a square or a section out of one side, not just straight across. Check Fabric no longer flags a shared edge digitized a hair apart (well inside tolerance) as an overlap - only a sliver wide enough to be a real one, matching how Align Edge already treats it.
    0.10.6 - Records and every fabric feature now record which user created or retired them (CreatedByUser/RetiredByUser/EditUser), filed documents get a SHA-256 recorded at filing time so a later mismatch is flagged before you open one, Parcel Lineage/History say plainly when a family's history is larger than what's shown instead of quietly cutting it off, a new record with no parcel id fills it in from the parcel Build gives it once every parcel it created shares one, fabrics now record which plugin version last opened them, and a new Parcel Report makes a one-page handout (area, record, lineage, footprint) for one parcel.
    0.10.5 - A parcel takes the lot that fits it best, not also the government lot around it, and new fabrics have longer Lot and Block fields so names aren't cut short
    0.10.4 - Parcel import: nothing is retired any more (a later edit date on a split retired its parent), polygons sharing a number become one parcel instead of being left out, all-zero numbers come in without a number, split history follows the parcel a split was cut out of, and is marked as inferred and kept out of the tax-roll change list; the calculated area is filled in. Importing parcels, lots, blocks or subdivisions, in any order, fills each parcel's subdivision, block and lot
    0.10.3 - Check Fabric opens at once and names each check while it runs. Import / Export shows a progress bar and which layer or parcel it is on.
    0.10.2 - Type a roll parcel ID, export the tax-roll shapefile and a change list, check gaps and overlaps, keep the daily tools on the toolbar, store subdivision lot width and depth, stack a condo or common area on one polygon, and show how far a legal description sits from the boundary. Labels add lot size and acreage over 1 acre. Import a polygon layer as current parcels, one record per parcel id (optional book, page, and date), with split history from -001, -002. Lots, subdivision blocks, and subdivisions import into their own tables. Fabric Settings > Parcel numbers sets the split separator, digit count, and parent suffix. Multi-polygon parcels keep true curves
    0.10.1 - Adjoining parcels can be traversed all the way round: courses along existing lines reuse them, a neighbour's line is split at a new corner, and corners within the fit distance are held to existing ones
    0.10.0 - One parcel number can have several polygons: Merge joins parcels that don't touch, Separate undoes it, a deed split's whole remainder keeps its number, closure reports and legal descriptions cover every polygon. Existing GeoPackage fabrics: Fabric Settings > Allow multi-polygon parcels (saves a copy first). Merge saves completely or not at all
    0.9.0 - Split a parcel by a deed's calls (Traverse > Split Selected Parcel): fits the deed to the parent, keeps the deed's dimensions, remainder keeps its number, commencement ties are run to the POB; Save only a good traverse; Remove mistake also undoes splits whose remainder kept its number; parcel numbers work with split PLSS layers, BLM National PLSS by default; start points keep every decimal; Web Mercator is refused; Split, Divide, Merge, Subdivide and Copy Parallel save to GeoPackage again; Parcel Lineage is no longer hidden by show-only-current
